AlgoLens · developer map

Follow one code run

AlgoLens helps a learner see how a supported method changes while it runs. Pattern simulation is modeled in the browser; Code execution runs a supported Python or Java method in a local Docker sandbox. These are separate modes.

Reference route — not an interactive learner tour

This map describes the implementation at commit 1607cc5. The app has since been tested with a real Java trace. This offline HTML file is a snapshot and may drift as code changes.

From Run button to explanation

A three-stop code route

Use VS Code Quick Open (Ctrl+P) to open each path; search for the named function.

1 · Input and result

src/ExecutionPanel.tsx

Find runCode(). It validates the JSON arguments, clears old trace data, sends the request to /api/trace, and stores the returned events for playback.

2 · Real execution

runner/server.py

Find Handler.do_POST() and run_in_sandbox(). The local service validates requests and runs the selected method in a fresh restricted Docker container.

3 · Evidence and wording

src/execution-explanations.ts

Find describeRuntimeStep() and explainSkippedJavaLoop(). The helper uses observed events and a narrow condition grammar; its tests include supported and rejected examples.

Boundary: this helper is deterministic, not an AI debugger. Unsupported conditions get a neutral message rather than an invented diagnosis.

To change this, start here

Change step-explanation wording or add a safe case

Start in src/execution-explanations.ts, then add a focused test in src/execution-explanations.test.ts. Keep unsupported forms on the non-diagnostic fallback path; never evaluate pasted code.

Change what appears beside a selected runtime step

Start in src/ExecutionPanel.tsx at the runtime trace panel. Keep the displayed explanation, source line, and values tied to the same selected event position.

Change startup ports or process messages

Start in scripts/start-local.mjs. The proxy target is wired from ALGOLENS_RUNNER_PORT in vite.config.ts; keep Vite on the runner's allowed local origins.

A practice to reuse

This project turned “explain why a loop didn't start” into a bounded requirement: explain only when an observed trace and supported condition prove the cause, otherwise avoid diagnosis. The corresponding implementation is src/execution-explanations.ts; tests in src/execution-explanations.test.ts cover a proven empty-array loop and an unsupported condition.

For another project, make the claim depend on evidence it can actually observe, then add one test for the supported case and one for the honest fallback.

Run the app and reopen this map

  1. In the project folder, run npm run start:local.
  2. Open the local URL printed in the terminal. Docker Desktop is needed for actual code execution; Pattern simulation remains browser-only.
  3. Open devpost/app-map.html in a browser for this offline reference. Refresh it after source changes if you need an updated map.
